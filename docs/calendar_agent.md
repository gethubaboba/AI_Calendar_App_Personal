# Локальный ассистент календаря

## Запуск в Windows

Из корня проекта запустите `.\calendar-dev.ps1 start`. Потребуются Docker Desktop с Linux-контейнерами, PowerShell, llama.cpp с поддержкой инструментов, файл модели GGUF и настроенные файлы окружения. При первом запуске Docker скачает зависимости.

1. Скопируйте `backend/.env.example` в `backend/.env` для новой установки и задайте собственный `SECRET_KEY`. Для PostgreSQL используйте хост `postgres`. При существующей базе следуйте порядку миграции в README.
2. Задайте `GRAFANA_ADMIN_PASSWORD` в корневом `.env`. Базовый Compose проверяет эту переменную при чтении конфигурации.
3. По умолчанию скрипт ищет `C:\llamacpp\llama-server.exe` и файл `Qwen3.8-27B-UD-Q4_K_XL.gguf` в корне проекта. Другие пути можно задать при запуске.

```powershell
.\calendar-dev.ps1 start -Binary 'D:\llama\llama-server.exe' -Model 'D:\models\calendar.gguf' -Port 8081
```

Скрипт ждёт готовности модели (по умолчанию 300 секунд, параметр `-TimeoutSeconds`), запускает PostgreSQL, API и Next.js, проверяет доступ к модели из контейнера API и открываемость страницы входа. После сообщения Ready перейдите на http://localhost:3000/agent и войдите в календарь. Модель загружается на Windows, GGUF исключён из контекстов сборки Docker.

```powershell
.\calendar-dev.ps1 stop
.\calendar-dev.ps1 stop -StopCompose
```

Первая команда завершает процесс llama-server, совпадающий с сохранёнными PID, путём и временем запуска. Вторая также останавливает web, backend и postgres данного Compose-проекта, включая уже работавшие сервисы. Данные PostgreSQL сохраняются. После ошибки запуска скрипт завершает модель, которую запустил сам. Состояние контейнеров проверьте командой `docker compose -f docker-compose.yml -f compose.agent.yml ps`; журналы модели находятся в `.calendar-dev/`.

Параметрам путей, порта и интерфейса соответствуют `CALENDAR_LLAMA_BINARY`, `CALENDAR_MODEL_PATH`, `CALENDAR_MODEL_PORT`, `CALENDAR_MODEL_BIND`. По умолчанию модель слушает 127.0.0.1:8080, API обращается к `http://host.docker.internal:8080/v1` и проверяет имя `calendar-qwen`. Адрес и имя переопределяются через `AGENT_MODEL_BASE_URL` и `AGENT_MODEL_NAME` в окружении PowerShell. Если конкретная сеть Docker не достигает loopback, укажите адрес частного адаптера Docker через `-Bind` и тот же адрес в URL для backend. Ограничьте входящие подключения сетью Docker. Сервер модели получает текст запроса и запрошенные события или заметки. В базовой конфигурации API и PostgreSQL публикуют порты согласно docker-compose.yml.

## Календарь, подтверждение и импорт

В режиме «Совет по календарю» ответ требует успешного чтения данных текущего пользователя. В режиме «Предложить изменение» ассистент может подготовить создание, редактирование или удаление события или заметки. Проверьте значения до и после изменения, затем нажмите «Подтвердить». Предложение действует десять минут, привязано к владельцу и применяется один раз. Если исходная запись изменилась или возник конфликт, потребуется новый предпросмотр.

Импорт принимает XLSX до 512 КиБ с одним листом и до 100 строк данных. Обязательные столбцы — `title` и `date`; дополнительные — `start_time`, `end_time`, `type`, `description`. Пример даты — `2026-11-12`, времени — `09:30`. Даты расписания должны укладываться в 365 дней. Предпросмотр показывает корректные строки и номера строк с ошибками, включая формулы, дубликаты и пересечения времени. Подтверждение сохраняет показанный набор одной транзакцией.

## MCP-клиенты

Адрес транспорта Streamable HTTP — `http://localhost:8000/api/agent/mcp`. Клиент передаёт заголовок `Authorization: Bearer <access_token>` с токеном входа в приложение. Реализованы `initialize`, `notifications/initialized`, `ping`, `tools/list` и `tools/call`. Инструменты `list_events` и `list_notes` читают записи владельца токена. `propose_change` возвращает предпросмотр. Интерфейс пользователя вызывает отдельный `POST /api/agent/confirm` с полем `proposal_id`. Эти операции используют обычный JWT приложения. Режим совета запрещает создание предпросмотра.

Из каталога backend запустите `python -m unittest -v test_mcp_calendar`. По умолчанию используется временная SQLite. Для проверки блокировок и транзакций укажите в `AGENT_TEST_DATABASE_URL` отдельную пустую PostgreSQL с применёнными миграциями.
