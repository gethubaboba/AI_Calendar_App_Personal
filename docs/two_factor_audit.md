# Аудит 2FA — 23 ноября 2026

В веб-версии добавлена добровольная двухфакторная аутентификация TOTP. Подключение находится на странице «Безопасность». Пароль проверяется перед настройкой, первый код подтверждает подключение. QR генерируется в браузере. При входе требуется второй шаг; после подключения выдаются десять одноразовых резервных кодов.

Секреты TOTP шифруются отдельным ключом `MFA_ENCRYPTION_KEY`, резервные коды и временные подтверждения входа хранятся в виде хешей. Ограничения попыток сохраняются в PostgreSQL. Подключение и отключение отзывают прежние сессии. Повторное использование кода и конкурентные запросы проверены.

## Проверки

- Серверный агент выполнил 31 тест в отдельной PostgreSQL, включая конкурентные запросы, отзыв сессий, восстановление, календарь, MCP и метрики. Миграция с 0003 сохранила существующий аккаунт и его прежние токены.
- В рабочей БД применена миграция 0004; `alembic check` не обнаружил расхождений. После обновления повторно прошли 16 прежних backend-тестов.
- Через HTTPS Funnel проверен полный цикл на временном аккаунте: настройка, подключение, TOTP-вход, резервный код, refresh, отказ старым токенам и отключение. Аккаунт удалён после проверки.
- Отдельно проверены preflight и вход через публичный ingress Funnel с обычной проверкой TLS, без локального маршрута MagicDNS: HTTP 200.
- TypeScript и статический экспорт Next.js с `/security/` прошли. GitHub Pages опубликовал реализацию из коммита `f0ae896`.
- Встроенный браузер Codex открыл форму, но отправка входа зависла до поступления запроса в API. Поэтому полный сценарий в браузере не подтверждён. В клиент добавлен тайм-аут: 20 секунд для запросов авторизации, 120 секунд для остальных запросов. Серверный публичный сценарий прошёл независимо.

## Исправление загрузки настроек

После сообщения владельца о `NetworkError` обнаружено, что ошибка необязательного запроса профиля блокировала форму 2FA, а успешный повтор не очищал старую ошибку. Страница теперь загружает статус MFA независимо от имени пользователя и очищает ошибку при повторе. После успешного подключения/отключения состояние берётся из результата операции, без дополнительного запроса, сбой которого мог ошибочно представить успешное действие как неудачное. Статическая сборка с проверкой TypeScript прошла. API после запуска Docker отвечает с правильным CORS; полное подтверждение настройки владельцем ещё требуется. Эти изменения не устанавливают причину всех прежних сетевых ошибок транспорта.
