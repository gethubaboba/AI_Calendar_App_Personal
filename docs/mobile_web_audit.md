# Мобильная веб-версия · 11 ноября 2026

## Исходные проблемы

В Edge при ширине 320 CSS-пикселей выбор 28-го числа в месяце и переход на неделю открывали другую неделю. При уменьшении высоты до 320 пикселей форма события начиналась выше экрана (y = −100,5), а кнопка отправки находилась ниже видимой области. В исходном коде также оставался устаревший запрет масштабирования. До исправления он уже отсутствовал в фактически отданном Edge теге viewport.

| Область | Изменение | Результат проверки |
| --- | --- | --- |

При задержке и ответе 503 календарь, заметки и аналитика показали загрузку и ошибку, после повтора открылись. |

## Среда и границы проверки

- В package.json есть скрипты dev, build и start. Производственная сборка прошла через `npm run build`, включая проверку типов Next.js.
- В Microsoft Edge с эмуляцией касаний проверены ширины **320, 375, 390 и 430 px**. Сначала использовались ответы API с тестовыми данными, затем производственная сборка с реальными маршрутами FastAPI и временной SQLite на loopback. Ошибки и задержки имитировались в браузере. Для графиков использовались данные о событиях.
- Отправка формы события проверена при высоте 320 px, заметки — 300 px. В итоговом viewport включён режим `interactive-widget=resizes-content`, масштабирование разрешено.
- Физический телефон, браузеры Android и iOS и Android-эмулятор для проверки были недоступны. На устройстве остаётся проверить ввод с настоящей клавиатурой, жест увеличения, системные отступы и подключение через Wi-Fi. Для сетевой приёмки откройте на телефоне `/health` по адресу API, войдите на сайте и сохраните событие. Проверка с временной SQLite не охватывала PostgreSQL.
