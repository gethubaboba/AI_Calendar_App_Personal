# Умный Календарь

Веб-клиент на Next.js, REST API на FastAPI и PostgreSQL. После входа по email и паролю доступны календарь, заметки и аналитика. В календаре выберите дату и нажмите «День», чтобы открыть список её записей.

## Запуск через Docker Desktop

Для локального календаря с MCP-ассистентом в Windows настройте окружение и выполните `.\calendar-dev.ps1 start` из корня проекта. Скрипт запускает модель, API, базу и веб-клиент. [Настройка, остановка и проверка MCP](docs/calendar_agent.md).

Понадобятся Docker Compose и Node.js 20 или 22 с npm. Команды ниже рассчитаны на PowerShell в корне репозитория.

1. Для новой установки скопируйте шаблон конфигурации.

   ```powershell
   Copy-Item backend/.env.example backend/.env
   ```

2. В `backend/.env` задайте собственный случайный `SECRET_KEY`. Для Compose оставьте имя хоста БД `postgres`. Если БД создана прежней версией приложения, сначала выполните переход, описанный ниже.

3. Запустите БД и API.

   ```powershell
   docker compose up -d --build
   docker compose logs backend
   ```

   Backend ждёт готовности PostgreSQL и выполняет `alembic upgrade head` перед запуском Uvicorn. Проверьте [состояние API](http://localhost:8000/health) и [контракт OpenAPI](http://localhost:8000/docs).

4. Запустите веб-клиент в отдельном терминале.

   ```powershell
   cd frontend
   npm ci
   npm run dev
   ```

   Откройте [календарь](http://localhost:3000). По умолчанию браузер обращается к `http://localhost:8000`. Для другого адреса укажите `NEXT_PUBLIC_API_URL` в `frontend/.env.local` до сборки или запуска клиента.

## Проверка с телефона по Wi-Fi

1. Подключите телефон и компьютер к одной локальной сети. В PowerShell выполните `ipconfig`. Возьмите **IPv4-адрес активного адаптера Wi-Fi** (или Ethernet, если компьютер подключён к этому же роутеру кабелем). Далее замените `<LAN-IP>` этим адресом.
2. В `frontend/.env.local` задайте `NEXT_PUBLIC_API_URL=http://<LAN-IP>:8000`. В `backend/.env` добавьте адрес веб-клиента в список разрешённых источников, например `CORS_ORIGINS=http://localhost:3000,http://127.0.0.1:3000,http://<LAN-IP>:3000`. Эти значения относятся к локальной проверке. Для публикации задайте адреса сайта и API в окружении развёртывания. Next.js подставляет публичный URL API при сборке.
3. Если используете Docker, примените настройки командой `docker compose up -d backend`. Compose уже запускает Uvicorn на `0.0.0.0:8000`. При запуске без Docker выполните подготовку БД из следующего раздела, затем из каталога `backend` запустите `.\venv\Scripts\python -m uvicorn main:app --env-file .env --host 0.0.0.0 --port 8000`.
4. Перезапустите `npm run dev` из каталога `frontend`. Скрипт слушает на `0.0.0.0`. Проверьте в терминале порт 3000. Если Next.js занял другой порт, используйте его в адресе сайта и в `CORS_ORIGINS`, затем перезапустите API.
5. На телефоне откройте сначала `http://<LAN-IP>:8000/health`, затем `http://<LAN-IP>:3000/auth`. Войдите с тестовой учётной записью и сохраните событие. Успешный вход подтверждает, что браузер может обратиться к API с источника сайта.
6. Если адреса недоступны, проверьте активный адаптер, изоляцию клиентов в гостевой Wi-Fi сети и разрешения брандмауэра Windows. При необходимости вручную разрешите входящие TCP-подключения на порты 3000 и 8000 только для частной сети и локальной подсети. Если страница и `/health` открываются, но вход не проходит, сверьте схему, IP и порт в обеих настройках.

## Запуск API без Docker

Установите PostgreSQL и Python 3.11 или 3.12. Создайте пользователя и базу (пример для локальной разработки):

```sql
CREATE USER planner WITH PASSWORD 'planner';
CREATE DATABASE planner_db OWNER planner;
```

В каталоге `backend` скопируйте `.env.example` в `.env`, задайте `SECRET_KEY` и адрес `DATABASE_URL=postgresql://planner:planner@localhost:5432/planner_db`.

```powershell
py -m venv venv
.\venv\Scripts\python -m pip install -r requirements.txt
.\venv\Scripts\python -m alembic upgrade head
.\venv\Scripts\python -m uvicorn main:app --reload --port 8000
```

## Переход с БД, созданной через create_all

Перед обновлением сохраните резервную копию. Если БД уже содержит таблицы приложения и у неё нет ревизии Alembic, сравните таблицы, поля, ключи и индексы с `backend/alembic/versions/0001_initial_schema.py`. При совпадении зарегистрируйте базовую схему **один раз** командой `alembic stamp 0001` из `backend`, затем выполните `alembic upgrade head`. В Compose для регистрации используйте `docker compose run --rm backend alembic stamp 0001`. При несовпадении сначала согласуйте схему на копии базы. Для пустой БД достаточно обычного запуска. После обновления `alembic check` проверяет соответствие моделей схеме.

## Конфигурация веб-версии

- `CORS_ORIGINS` — список адресов веб-клиента через запятую. Локальные значения в шаблоне — `http://localhost:3000,http://127.0.0.1:3000`. Для доступа с другого устройства укажите адрес клиента в локальной сети и доступный устройству адрес API.
- В колокольчике напоминание появляется в дату события по календарю браузера. Нажатие отмечает его прочитанным. Доставка по email и push отложена.
- Аналитика считает события за выбранный период, а карточка «Всего заметок» показывает все отдельные заметки пользователя.
- Для дополнительного анализа нужен Ollama с моделью `qwen2.5:1.5b`. Модель задаётся через `OLLAMA_MODEL` в окружении backend. Для запуска API на хосте адрес по умолчанию — `http://localhost:11434/v1`. В Docker Desktop используется `http://host.docker.internal:11434/v1`; переопределите `OLLAMA_BASE_URL` в окружении Compose при другом расположении сервиса.
